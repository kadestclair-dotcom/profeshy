## 1. The question

From S4 results §4: does ForeverDB supply the names and data for the auction-house items that Blizzard's item endpoint (`/data/wow/item/{id}`, `static-forever-us`) returns 404 for? F2 is the secondary check: do ForeverDB's per-profession recipe counts agree with Blizzard's?

## 2. What happened on 2026-11-18, in order

1. **11:18, keyed run, F1 0/25, F2 status −1** (`s4_run_log_2026-11-18_1118_keyed_certfail.*`). Status −1 means no HTTP answer at all. The cause was TLS: Windows Python could not validate ForeverDB's Let's Encrypt chain (YE1 → Root YE → ISRG Root X2) because ISRG Root X2 was missing from the trust store. The owner added the self-signed ISRG Root X2 to CurrentUser\Root. **This was a transport failure, not a negative result.** The cause rests on the 11:49 pre-fix diagnostic (`fdb_diag_log_2026-11-18_certfail.json`, SHA-256 `8ed5c4e5698f`; step 3) and on the fix working. ## 6. Findings (observations, not code)

- **(a) Watermark.** The `description` fields returned by `/professions` carry an invisible zero-width character sequence. Seen in two response snippets (`fdb_diag_log.json`, D2 and D4 body heads): U+2063 delimiters around a pattern of U+200B and U+200C. That fits a per-key fingerprint, and ForeverDB's approval says use is tracked per developer ID; that is a Hypothesis, not tested. **0 of 25 item names carried one** (`s4_run_20261118-122551.json`, names recorded verbatim). Whether other ForeverDB text fields carry it is untested. Consequence: any ForeverDB description text Profeshy displays would carry the sequence, and removing it may conflict with ForeverDB's terms. How to handle it is the owner's decision, after reading the terms. Claim level: observation (one diagnostic run).
- **(b) User-Agent.** Python's default User-Agent was accepted once (diagnostic D4: 200), although ForeverDB's docs say Cloudflare rejects it (`S4_F3_FOREVERDB_TERMS_2026-11-14.md`). That is one observation. Keep sending a User-Agent that names the app.
- **(c) Certificate.** On Windows, Python needed ISRG Root X2 in the trust store to validate ForeverDB's chain (§2 step 1). Any new machine or CI runner that calls ForeverDB should check this first.

## 7. Limits

- **One run, one day.**
- **25 items, not a random sample.** They are the 25 example IDs S1b recorded out of the 265 that returned 404 in its 500-item sample (S1b results T6). How well ForeverDB covers the other 240 is **untested**.
- **Name correctness is not verified.** ForeverDB describes its data as client extraction plus player-addon observations (`S4_F3_FOREVERDB_TERMS_2026-11-14.md`). Nothing here checks its names against the game.
- **Nothing here says whether caching or storing ForeverDB data is allowed.** The terms on record cover access, limits and credit, not retention.

## 8. Implications for the Contract (proposals, not decisions)

- The **hybrid source strategy** (S4 results §5: Blizzard for professions, recipes and reagents; ForeverDB for item names in the auction long tail) holds on this sample.
- The **credit link** to https://foreverdb.net is a licence condition on every screen that shows ForeverDB data (free tier).
- **Privacy:** ForeverDB's approval email states that it logs per key the endpoints, items, requesting site, program kind and country (approval record, held in Notion; not appended to the review package). What ForeverDB actually logs is not technically verified. Calling ForeverDB from users' phones would send those details about each user to ForeverDB, which the privacy policy (D-Priv, terms register §1 §2.15) would have to disclose. A backend calling ForeverDB on Profeshy's behalf avoids that. This is input to D4.
- **Free-tier limits** (5,000 requests/day, 30/min) set against about 5,015 distinct items per house (S1b T6; S2 A2). One lookup per item would use the whole daily quota for a single house. That only works if names are looked up once and kept, which is the open caching question below.
- **Open terms questions:** may ForeverDB data be cached or stored, and for how long; and how must the watermark be handled.
