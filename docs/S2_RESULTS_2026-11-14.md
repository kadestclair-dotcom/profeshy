## What this proves

- The backend→phone sync for one full house is **~67 KB compressed** —
  smaller than a single photo. The 13 MB problem is entirely a
  server-side problem, and server-side it costs ~3 s of Python.
- The on-device store for a house is a **180 KB SQLite file** with
  sub-millisecond lookups on desktop SQLite. Android numbers will be
  worse; Part B exists to measure how much worse, and the design's
  discipline stands: these desktop figures are a floor estimate,
  never to be quoted as phone performance.
- **Incidental cadence datapoint for S3:** the S2 capture at 18:41 was
  byte-identical to S1b's at 18:27 (same 131,205 auctions) — the
  house 113 snapshot did not change across that ~14-minute window.
  One observation, consistent with hourly-ish snapshots; T9's formal
  comparison remains open.

## Hand-offs

- **D4/G2:** the serving contract now has numbers — per house per
  snapshot: ~3 s server processing, ~67 KB per syncing client.
- **S3:** history storage sizing can use the aggregate form (533 KB
  JSON / 180 KB SQLite per house-snapshot) instead of the raw 13 MB.
- **Part B:** reuses `s2_house113.db` from this run (kept on the

## Part B — Android re-measure (2026-11-14)

**Run:** 2026-11-14 20:41:38 PST, owner's phone via Termux, harness

**Device:** Samsung SM-G975U (Galaxy S10+), Android 12,
Python 3.14.10 under Termux. A 2019 flagship — a fair stand-in for a
mid-range target device, not a best case.

| Test | Measured | Bar | Result |
|---|---|---|---|
| B0 Open DB | 5.42 ms | — | — |
| B1 Lookup by item ID | **3.3 ms** (desktop 0.13 ms) | ≤ 50 ms | PASS |

Same battery and best-of method as Part A A4. The phone is roughly
8–25× slower than desktop SQLite depending on the query class, and
it does not matter: the slowest class clears the 50 ms bar by ~10×.
Every query a price screen would run is effectively instant on
2019 hardware.

**Caveat:** Termux Python is not the shipping runtime — a real
Android app would use its own SQLite stack, plausibly faster. Part B
is a floor check on the aggregate-on-device design, and the design
holds. Claim level: Tested (one device, one run).
